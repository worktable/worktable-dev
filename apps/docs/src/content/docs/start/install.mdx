Run Worktable on your computer or a server you control, on macOS or Linux
(arm64 or x64). For the native macOS app, use
[Worktable Desktop](/start/desktop/). To skip running a machine, use
[Worktable Cloud](/guides/worktable-cloud/).

<InstallCommand />

The installer sets up the `worktable` command (shorthand `wtb`) and starts
setup. When it finishes, open the address it prints. The default is:

```text
http://localhost:7480
```

## Inspect the installer

The installer needs no sudo and does not edit shell profiles. Preview what it
downloads and changes:

```sh
curl -fsSL https://worktable.dev/install | sh -s -- --dry-run
```

See the [installer reference](/reference/installer/) for every flag and path.

## Choose the workspace folder

Your workspace is a plain folder, `~/Worktable` by default. It is kept apart
from app settings and credentials.

Pick another folder during setup, or set it explicitly:

```sh
worktable setup --workspace ~/work/notebook
```

To pick one at launch, use `worktable launch --workspace ~/work/notebook`.
Setting `WORKTABLE_WORKSPACE` does not override the CLI's saved settings or
flags.

Worktable can adopt an existing workspace. It refuses to initialize a non-empty
unrelated folder or overwrite another workspace's identity.

## Choose how it runs

Setup offers a background service or a foreground process. Use the background
service if agents should reach Worktable after you close the terminal.

To reach the server from another machine, finish local setup first, then follow
[Remote access](/guides/remote-access/).

## Linux servers

Run Worktable as a regular user, not root. Agents see Drawings and HTML Docs
through previews rendered in a sandboxed browser, and that sandbox can't start
as root.

On Ubuntu 23.10 and later, run this once as the user that runs Worktable:

```sh
worktable preview setup
```

It asks for sudo to add an AppArmor rule for the preview browser. The rule
matches the browser's path under your account, so anything your account puts at
that path can also create user namespaces.

`worktable doctor` and **Settings → System** show whether previews work. On a
minimal server, `doctor` also names missing system libraries and, on Debian or
Ubuntu, the command to install them. Everything else works without previews.

## Verify the install

```sh
worktable doctor
```

It reports the active workspace, service, and agent setup.

## Non-interactive installs

```sh
# Accept defaults without prompts
curl -fsSL https://worktable.dev/install | sh -s -- --yes

# Install only; run setup yourself later
curl -fsSL https://worktable.dev/install | sh -s -- --no-setup
```

You can also pass `--workspace`, `--port`, `--background` or `--foreground`,
and `--mcp <client-ids>`. See the [installer reference](/reference/installer/).
